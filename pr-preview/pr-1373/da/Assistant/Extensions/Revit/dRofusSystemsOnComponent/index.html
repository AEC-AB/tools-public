dRofus Systems On Component

Dette indhold er ikke tilgængeligt i dit sprog endnu.

Description

Section titled “Description”

The dRofus Systems On Component extension automatically synchronizes system information from dRofus and writes it to Revit element parameters. This powerful tool enables you to maintain consistent system assignments across your BIM model by pulling system data directly from your dRofus database and writing it to specific Revit parameters based on customizable pattern matching rules.

Key Benefits:

  • Automates system data transfer from dRofus to Revit
  • Supports flexible pattern matching with regular expressions
  • Handles both main occurrences and sub-items (e.g., HVAC dampers with actuators)
  • Processes multiple elements in a single operation
  • Provides detailed feedback on success and warnings

Typical Use Cases:

  • Updating electrical system parameters on MEP equipment
  • Assigning automation system codes to building control components
  • Synchronizing HVAC system information across air handling equipment
  • Maintaining system documentation in Revit from dRofus source of truth

Configuration

Section titled “Configuration”

Elements to Update

Section titled “Elements to Update”

Select the Revit elements that should receive system information from dRofus.

How to Configure:

  • Use the filter interface to select elements by category, type, parameters, or other criteria
  • Common selections: All MEP equipment, specific families, elements in a view, or elements with specific parameter values
  • Important: Only elements with a valid dRofus occurrence ID will be processed

Example Filters:

  • All Mechanical Equipment in the active view
  • All elements where “drofus_occurrence_id” is not empty
  • All elements of family type “VAV Terminal”

System to Property Mapping

Section titled “System to Property Mapping”

Define how dRofus system numbers should be mapped to Revit parameters using pattern matching.

Configuration Format:

  • Key: Regular expression pattern to match system numbers
  • Value: Name of the Revit parameter to write matched systems to

Understanding System Numbers: dRofus system numbers typically follow formats like:

  • =4330.005:01 (Electrical system)
  • =5640.003:05 (Automation system)
  • =5690.001:02 (Control system)

Pattern Examples:

Pattern What It Matches Use Case
=43.* All systems starting with =43 All electrical systems (43xx series)
=56.* All systems starting with =56 All automation systems (56xx series)
=43\d+\.\d+:\d+ Precise format like =4330.005:01 Electrical systems with full format validation
=56\d+\.\d+:\d+ Precise format like =5640.003:05 Automation systems with full format validation
=4330.* All systems starting with =4330 Specific electrical subsystem

Example Configuration:

Result: If a damper has systems =4330.005:01 and =4331.002:03, the parameter “Electrical_Systems” will be set to =4330.005:01;=4331.002:03

Multiple Systems: When multiple systems match a pattern, they are joined together using the separator you define (see “List Separator” below).

Sub-Items: Systems from sub-items (like actuators on dampers) will be included if “Include sub-items” is enabled.

Include Sub-items

Section titled “Include Sub-items”

Control whether systems from dRofus sub-items should be included when fetching system information.

Setting: Checkbox (Enabled by default)

When Enabled (Recommended):

  • Systems from both the main occurrence AND all its sub-items are retrieved
  • Provides complete system picture for complex components

Example: An HVAC damper occurrence:

  • Main item: Fire damper (on ventilation system =5640.003:05)
  • Sub-item 1: Actuator (on automation system =5690.001:02)
  • Sub-item 2: Control unit (on automation system =5691.005:01)

With “Include sub-items” enabled, all three systems would be captured and written to your Revit parameters according to your mapping rules.

When to Disable:

  • You only want systems directly assigned to the main occurrence
  • Sub-item systems should be handled separately
  • Performance optimization for very large projects (fewer API calls)

dRofus Occurrence Parameter

Section titled “dRofus Occurrence Parameter”

The name of the Revit parameter that contains the dRofus occurrence ID.

Default Value: drofus_occurrence_id

About This Setting: This parameter acts as the “link” between your Revit elements and dRofus occurrences. Each Revit element must have this parameter populated with a valid dRofus occurrence ID to be processed.

Supported Parameter Types:

  • Project parameters
  • Shared parameters
  • Built-in parameters (if containing occurrence IDs)

Value Format: The parameter can contain:

  • Integer values (e.g., 12345)
  • String representations of integers (e.g., "12345")

Validation: If this parameter is missing or empty on an element, that element will be skipped with a warning.

List Separator

Section titled “List Separator”

Character(s) used to join multiple system numbers when writing to a single parameter.

Default Value: ; (semicolon)

How It Works: When multiple systems match your pattern for a single element, they need to be combined into one text string. This setting defines what character(s) separate them.

Example with ; separator:

Common Separator Options:

Separator Result Best For
; =4330.005:01;=4331.002:03 Most compact, clear separation
, =4330.005:01, =4331.002:03 More readable, slightly longer
| =4330.005:01 | =4331.002:03 Visual distinction, good for reports
\n =4330.005:01
=4331.002:03		 Multi-line parameters (less common)

Recommendation: Use ; (semicolon) for compatibility with most Revit parameter types and schedules.

Functionality

Section titled “Functionality”

Description

Section titled “Description”

The extension performs the following operations for each selected element:

  1. Authentication: Automatically connects to the dRofus database using project information stored in your Revit model
  2. Element Processing: For each selected element:
    • Retrieves the dRofus occurrence ID from the specified parameter
    • Calls the dRofus API to get all systems associated with that occurrence
    • Optionally includes systems from sub-items (actuators, controls, etc.)
  3. Pattern Matching: Applies your regex patterns to the retrieved system numbers
  4. Parameter Writing: Writes matched systems to the corresponding Revit parameters
  5. Reporting: Provides a summary of processed elements and any warnings encountered

Performance Optimization: The extension uses stream processing, meaning each element is processed completely before moving to the next. This minimizes memory usage and allows for cancellation of long-running operations.

How to Use

Section titled “How to Use”

Prerequisites

Section titled “Prerequisites”
  1. dRofus Connection: Your Revit model must have dRofus connection information configured (typically done during initial setup)
  2. Occurrence IDs: Elements must have their dRofus occurrence ID parameter populated
  3. Target Parameters: The Revit parameters you want to write to must exist in the project (create them as project or shared parameters if needed)

Step-by-Step Process

Section titled “Step-by-Step Process”

Step 1: Prepare Your Revit Parameters

Before running the extension, ensure the target parameters exist:

  1. Open Revit’s Project Parameters dialog (Manage tab > Project Parameters)
  2. Create parameters for your system assignments:
    • Parameter Name: Electrical_Systems (Text parameter)
    • Parameter Name: Automation_Systems (Text parameter)
    • Parameter Name: Fire_Safety_Systems (Text parameter)
  3. Assign these parameters to the appropriate categories (Mechanical Equipment, Electrical Equipment, etc.)

Step 2: Launch the Extension

  1. Open the Assistant platform
  2. Create a new task or open an existing workflow
  3. Add the “dRofus Systems On Component” extension

Step 3: Configure Element Selection

  1. Click on the “Elements to update” field
  2. Use the filter interface to select your target elements:
  3. Preview the selection to verify the correct elements are included

Step 4: Configure System Mappings

Add mapping rules for each system type you want to capture:

Pattern (Key) Target Parameter (Value)
=43.* Electrical_Systems
=56.* Automation_Systems
=59.* Fire_Safety_Systems

Step 5: Configure Additional Settings

  • Include sub-items: Leave checked (recommended) to capture systems from actuators, controls, etc.
  • dRofus occurrence parameter: Verify this matches your parameter name (default: drofus_occurrence_id)
  • List separator: Leave as ; or adjust to your preference

Step 6: Execute the Extension

  1. Click “Run” to start the process
  2. Monitor the progress indicator
  3. Review the results message:
    • Success: “Systems updated successfully on X elements”
    • Partial Success: “Systems updated on X elements with warnings:” followed by specific warnings
    • Failure: Error message with details

Step 7: Verify Results

  1. Select a processed element in Revit
  2. Check the Properties palette or use a schedule
  3. Verify that your target parameters now contain the dRofus system numbers
  4. Example verification:
    • Element: Fire Damper #042
    • Electrical_Systems: =4330.005:01;=4335.010:05
    • Automation_Systems: =5690.001:02

Troubleshooting

Section titled “Troubleshooting”

Issue 1: “No elements selected” Error

Section titled “Issue 1: “No elements selected” Error”

Symptom: Extension fails immediately with message “No elements selected”

Causes:

  • Element filter returned no results
  • Filter is not properly configured
  • Elements don’t match the filter criteria

Solution:

  1. Review your element filter configuration
  2. Use Revit’s Filter tool to preview what elements match your criteria
  3. Ensure elements exist in the active view/document
  4. Check that your category or parameter-based filters are correct

Issue 2: “Could not find parameter [ParameterName] on element [ElementId]”

Section titled “Issue 2: “Could not find parameter [ParameterName] on element [ElementId]””

Symptom: Warning messages about missing parameters on specific elements

Causes:

  • Target parameter doesn’t exist in the project
  • Parameter exists but isn’t assigned to the element’s category
  • Parameter name spelling mismatch in configuration

Solution:

  1. Open Project Parameters (Manage > Project Parameters)
  2. Verify the parameter exists and spelling matches exactly
  3. Ensure the parameter is assigned to all necessary categories
  4. Check element type parameters vs instance parameters
  5. If using shared parameters, verify they’re properly loaded

Resources:

  • Revit Project Parameters Guide (link)
  • Understanding Parameter Types (link)

Issue 3: “Failed to get systems for occurrence [ID]”

Section titled “Issue 3: “Failed to get systems for occurrence [ID]””

Symptom: Some elements are skipped with API error messages

Causes:

  • dRofus occurrence ID doesn’t exist in the database
  • Network connectivity issues with dRofus server
  • dRofus API authentication problems
  • Occurrence has no systems assigned in dRofus

Solution:

  1. Verify the occurrence ID exists in dRofus
  2. Check network connectivity to dRofus server
  3. Verify dRofus connection settings in Revit model
  4. Log into dRofus web interface to verify occurrence and system assignments
  5. Contact dRofus administrator if IDs appear incorrect

Resources:

  • dRofus Connection Setup Guide (link)
  • dRofus API Status Page (link)

Issue 4: Regex Pattern Not Matching Expected Systems

Section titled “Issue 4: Regex Pattern Not Matching Expected Systems”

Symptom: Parameter remains empty or contains unexpected systems

Causes:

  • Regex pattern doesn’t match actual system number format
  • Special characters not properly escaped in pattern
  • System numbers in dRofus have different format than expected

Solution:

  1. Review actual system numbers in dRofus for the test occurrence
  2. Use a regex testing tool to verify your pattern: https://regex101.com/
  3. Remember to escape special characters:
    • . becomes \.
    • * is a wildcard (use .* to match anything)
    • = doesn’t need escaping
  4. Start with a simple pattern like =43.* and refine from there
  5. Test with a single element before processing many

Common Pattern Corrections:

Incorrect Correct Why
=43. =43\. or =43.* Period needs escaping or use .* wildcard
=43* =43.* * alone is invalid, use .* for wildcard
=43\d =43\d+ Need + for “one or more digits”

Resources:

  • Regex Tutorial: https://regexone.com/
  • Regex Tester: https://regex101.com/
  • Regular Expression Quick Reference (link)

Issue 5: Performance - Extension Takes Too Long

Section titled “Issue 5: Performance - Extension Takes Too Long”

Symptom: Extension runs slowly on large element sets

Causes:

  • Processing thousands of elements
  • Network latency to dRofus server
  • Many API calls due to “Include sub-items” being enabled

Solution:

  1. Process elements in smaller batches (by level, by area, etc.)
  2. Run during off-peak hours for network efficiency
  3. Consider disabling “Include sub-items” if sub-item systems aren’t needed
  4. Use more specific element filters to reduce processing scope
  5. Check network connection quality to dRofus server

Performance Expectations:

  • ~10 elements/second with sub-items enabled
  • ~20 elements/second with sub-items disabled
  • Network latency significantly impacts speed

Issue 6: “Operation was cancelled”

Section titled “Issue 6: “Operation was cancelled””

Symptom: Process stops with cancellation message

Causes:

  • User manually cancelled the operation
  • Assistant platform timed out the task
  • System resource constraints

Solution:

  1. If you cancelled, simply rerun when ready
  2. For timeouts, process fewer elements per batch
  3. Check system resources (memory, CPU) if unexpected
  4. Break large projects into multiple runs

FAQ

Section titled “FAQ”

Q: When should I use this extension versus manual parameter updates?

  • A: Use this extension when you have multiple elements that need system assignments synchronized from dRofus. It’s especially valuable when:

    • You have dozens or hundreds of elements to update
    • System assignments change frequently in dRofus
    • You need to maintain consistency between dRofus and Revit
    • You’re working with complex components that have multiple systems

    Manual updates are better for: Single elements, one-off corrections, or when dRofus data isn’t the source of truth.

Q: Can I update systems for elements across multiple Revit views or the entire project?

  • A: Yes! The element filter can select elements from:

    • Current view only
    • All views
    • Entire project
    • Specific worksets
    • Based on any parameter criteria

    Simply configure your filter accordingly. For large projects, consider running in batches by level or area.

Q: What happens if an element has systems that match multiple patterns?

  • A: Each pattern maps to a separate parameter, so this works perfectly. For example:
    • Pattern =43.* → writes to Electrical_Systems parameter
    • Pattern =56.* → writes to Automation_Systems parameter
    • An element with systems =4330.005:01 and =5640.003:05 will have both parameters populated correctly.

Q: Can I use the same pattern to write to multiple parameters?

  • A: No, each pattern should map to one parameter. If you need the same data in multiple places, create multiple mappings with the same pattern but different target parameters.

Q: How often should I run this extension?

  • A: Run frequency depends on your workflow:
    • Weekly: For active design phases with frequent dRofus updates
    • Before milestones: Before submissions, coordination meetings, or deliveries
    • After bulk changes: When system assignments are updated in dRofus for many elements
    • On-demand: When specific coordination is needed

Q: Will this extension overwrite existing parameter values?

  • A: Yes, the extension will overwrite the target parameters with current dRofus data. If no systems match a pattern, the parameter will be cleared (set to empty). This ensures your Revit model always reflects current dRofus system assignments.

Q: What if some elements have no dRofus occurrence ID?

  • A: Elements without a valid occurrence ID are automatically skipped. The extension will continue processing other elements and won’t generate errors. Consider using a filter like "drofus_occurrence_id" is not empty to exclude these elements upfront.

Q: Can I use this with families from different manufacturers?

  • A: Yes! The extension works with any Revit family as long as:
    • The element has a parameter containing the dRofus occurrence ID
    • The element has (or you create) parameters for the system assignments
    • The element’s category is compatible with your parameter assignments

Q: How do I handle elements with many systems (10+)?

  • A: This is common for complex equipment. The extension handles this automatically:
    • All matching systems are joined with your separator
    • Revit text parameters can hold thousands of characters
    • Consider creating multiple parameters for different system types (electrical, automation, fire, etc.) rather than one combined parameter
    • Use schedules to split or analyze the concatenated values if needed

Q: What’s the difference between this extension and the dRofus Occurrence Sync extension?

  • A:

    • dRofus Systems On Component (this extension): Specifically focuses on synchronizing system assignments using pattern matching. Great for MEP coordination and system documentation.
    • dRofus Occurrence Sync: Broader synchronization of any dRofus attributes (not just systems) using attribute configuration mappings. More comprehensive but requires attribute configuration setup.

    Use this extension when you primarily need system synchronization with flexible pattern-based rules.

Best Practices

Section titled “Best Practices”
  1. Start Small: Test with 5-10 elements before processing hundreds
  2. Verify Patterns: Use regex101.com to test patterns before applying
  3. Document Mappings: Keep a record of your pattern-to-parameter mappings
  4. Regular Updates: Schedule regular runs to keep systems synchronized
  5. Use Schedules: Create Revit schedules to audit system assignments
  6. Backup First: Run on a local copy before applying to central model
