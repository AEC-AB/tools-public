Upgrade old macro to extension

Upgrading a Revit Macro to a Revit Extension involves adapting your existing code to the new extension model used by Assistant. This guide will walk you through the changes you need to make and help you transition seamlessly.

Note

The same principles apply to Tekla, AutoCAD and Navisworks macros.

Why Upgrade?

Section titled “Why Upgrade?”
  • Revit Macros are legacy, and the new extension model provides improved functionality and compatibility.
  • The new model is designed for use with Assistant, offering a more integrated and efficient workflow.
  • You can leverage advanced features and access variables through the context, enhancing your extension’s capabilities.

Key Changes

Section titled “Key Changes”

Return Type

Section titled “Return Type”
  • In the new extension, the Execute method is replaced by the Run method.
  • The new extension uses an interface that defines the args and result classes as types.
  • The return type is TextExtensionResult, which provides a more structured response.

Transition Steps

Section titled “Transition Steps”
  1. Update the method signature to match the new extension model, using Run instead of Execute.
  2. Change the return type to TextExtensionResult in your method.
  3. Update .csproj to the new standard
  4. Create a Configurations.targets file and paste the content shown below
  5. Add nuget source to nuget.config file
  6. Add tasks.json (optional)
  7. Add Global usings (optional)
  8. Remove any separate logging mechanisms specific to the old Macro model.
  9. Remove global exception handling or return specific exceptions as a Result.
  10. Add VS Code settings file.
  11. Move the content in Readme.md to this wiki, see process here Writing help files for Extensions

8. Logging (optional)

Section titled “8. Logging (optional)”
  • The new extension model does not support a separate logging system.
  • Logging should be done by using the result class or the variables in the context class.

Exception Handling

Section titled “Exception Handling”
  • You don’t need to handle exceptions in the new extension model for logging purposes.
  • Assistant will capture exceptions and their messages, so explicit exception handling for logging is not required.

9. Exception Logging

Section titled “9. Exception Logging”
  • If you need to log something during execution, you can set a variable or include log messages as text in the result.
  • This aligns with the new extension model’s design and simplifies the logging process.
  • Do not handle generic exceptions.
